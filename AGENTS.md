# Repository Guide

## Commands

- Use Bun: `bun install`, `bun dev`, `bun run build`, and `bun start`. The CI workflow also installs with Bun.
- `bun run build` is the available green verification; this repo defines no test, lint, or typecheck scripts.
- Do not use `bunx tsc --noEmit` as a required check until the existing ref-type error in `src/components/ui/button.tsx` is resolved.

## Application

- This is one TanStack Start/Vinxi application. Browser, SSR, and API handlers start at `src/client.tsx`, `src/ssr.tsx`, and `src/api.ts`.
- Routes are file-based under `src/routes/`; API endpoints use `createAPIFileRoute`. `src/routeTree.gen.ts` is generated by TanStack Router (including during `bun run build`) and must not be edited.
- Use the `@/` alias for `src/` imports. shadcn component aliases and Tailwind source CSS are defined in `components.json`.

## Deployment And Secrets

- `sst.config.ts` deploys the AWS Lambda preset in `eu-west-1`. Pushes to `main` trigger CI deployment with `bunx sst deploy --stage prod`.
- The SST `GitHubFunction` uses `src/functions/github.handler` and receives `GH_TOKEN`; SST injects its URL as `VITE_GITHUB_FUNCTION_URL` for the site. Keep tokens in ignored environment files, never source or commit them.
